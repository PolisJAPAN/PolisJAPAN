## 1. 副作用の分類（全画面共通）

各操作が、本番のデータや他の利用者に影響するかを 3 段階で分類する。本番テストで実行してよいのは A と B だけである。

| 分類 | 意味 | 例 |
| --- | --- | --- |
| **A** | 読み取りのみ。ブラウザの表示が変わるだけ | 検索、並び替え、タブ切替、ページ遷移 |
| **B** | そのブラウザの中だけに状態を保存する（Cookie・localStorage） | お気に入り、チュートリアルの非表示設定、入力途中の下書き |
| **C** | サーバーや外部サービスにデータを送る。本番データ・費用・他の利用者に影響する | テーマ投稿、AI 生成、お問い合わせ送信、投票 |

**C に当たる操作は、利用者向けの画面全体で次の 5 つだけである。**

| # | 操作 | 画面 | 実際に起きること |
| --- | --- | --- | --- |
| C1 | pol.is 埋め込み内での投票・意見投稿 | アプリ：テーマ詳細 | pol.is の実テーマに記録される。約 5 分後に分析表示へ反映され、全利用者の表示が変わる |
| C2 | AI 生成ボタン（3 種） | アプリ：テーマ作成（AI アシスト） | 本番 API 経由で OpenAI を呼び出し、費用が発生する。データは保存されない |
| C3 | 「テーマを作成」（投稿ボタン） | アプリ：テーマ作成 | 下書きが承認済みで登録され、約 15 分以内に pol.is に実テーマが作られて一般公開される |
| C4 | 「送信する」 | アプリ：お問い合わせモーダル | 運営宛てと、入力したアドレス宛てに実メールが 1 通ずつ送られる |
| C5 | 「お問い合わせ送信」 | LP：お問い合わせ | 同上 |

管理画面の操作（承認・編集・削除・「更新」）は、ほぼすべて C である（§7）。

## 2. アプリ共通（app.pol-is.jp）

### 2.1 データの読み込み

- テーマ一覧と分析結果は、S3 上の CSV を CloudFront 経由で直接読む。API は呼ばない。
- CSV の URL には `?_v=<5分ごとに変わる数値>` が付く（`Math.floor(Date.now()/300000)`）。同じ 5 分間は同じ URL になる。
- バッチが CSV を更新するのは 5 分間隔なので、投票や投稿が画面に反映されるまで最大 10 分ほどかかる。

### 2.2 API の呼び出し

- API の宛先は、ホスト名が `localhost` のとき `/api/`、それ以外は `https://api.pol-is.jp/`。
- API を呼ぶのはテーマ作成モーダルだけである（§5）。
- `localhost` の `/api/` と `/csv/` は、ローカルの nginx が**本番へ中継する**。ローカルで操作しても C の操作は本番に影響する。

### 2.3 ブラウザに保存するデータ

| 種類 | キー | 値 | 書き込むとき | 効果 |
| --- | --- | --- | --- | --- |
| Cookie | `tutorial_last_shown` | `YYYYMMDD`（午前 4 時で日付が変わる） | チュートリアルを自動表示したとき | 同じ日は自動表示しない |
| Cookie | `tutorial_optout` | `1` | 「次回から表示しない」を ON にしたとき（OFF で削除） | 自動表示しない |
| Cookie | `notice_last_seen_id` | 最新のお知らせ ID（現在 `6`） | お知らせモーダルを開いたとき | 未読が無ければ自動表示しない |
| localStorage | `favorite_conversations` | conversation_id の JSON 配列 | ☆／★ を押したとき | お気に入りタブと星の表示 |
| localStorage | `favorite_notice_shown` | `1` | お気に入りの初回ダイアログを出したとき | 2 回目以降はトーストになる |
| localStorage | `contact_draft` | `{mail, name, content}` の JSON | お問い合わせの入力時（300ms 後） | 入力内容の復元。送信成功時に削除 |
| localStorage | `AI_ASSIST_CREATE_DRAFT_*` / `MANUAL_CREATE_DRAFT_*`（`THEME` `AXIS` `COMMENTS` `DESCRIPTION` `CATEGORY`） | 入力内容（複数項目は `###br###` 区切り） | テーマ作成の入力時 | 入力内容の復元。投稿成功時に、そのモードの分だけ削除 |
| Cache Storage | `img-cache-v1` | チュートリアル画像など 18 点 | Service Worker の初回登録時 | 画像をキャッシュから返す |

- Cookie の有効期限は 365 日、`path=/`、`SameSite=Lax`（Secure 属性なし）。
- sessionStorage は使っていない。
- サーバーに利用者の識別情報を送る仕組み（ログイン・アナリティクス）は無い。

### 2.4 チュートリアルとお知らせの自動表示

画面を開いた直後に、次の順でオーバーレイが出る。自動テストでは、これらがクリックを遮る点に注意する。

1. **チュートリアル**（800ms 後）: `tutorial_optout` が `1` でなく、かつ今日まだ自動表示していないとき。初回だけでなく、オプトアウトするまで**毎日 1 回**表示される。ホームと詳細で同じ Cookie を使う。
2. **お知らせ**（2000ms 後、ホームのみ）: 未読のお知らせがあるとき。チュートリアル表示中は、閉じられてから 400ms 後に開く。

事前に Cookie `tutorial_optout=1` と `notice_last_seen_id=6` を入れておけば、どちらも表示されない。

### 2.5 モーダルの共通動作

- 開いているモーダルには `.show` が付く。
- 閉じ方は `.modal-close-button` を押すか、背景をクリックする。Esc キーでは閉じない。
- 閉じても入力内容は消えない。

### 4.3 分析の表示規則

- 入力は pol.is の `comment-groups.csv`（意見ごとの賛成・反対・パスの件数と、グループ別の件数）。
- **みんなが賛成した意見**
  - グループが 2 つ以上あるとき: 各グループの賛成率 `(賛成+1)/(投票+2)` を掛け合わせた値の大きい順（Polis 本家の group-aware consensus と同じ式）。同じ値なら投票数の多い順。
  - グループが 1 つ以下のとき: 全体の賛成率の高い順。同じ値なら投票数の多い順。
- **グループ X が賛成した意見**: そのグループの賛成率の高い順。同じ値ならそのグループの投票数の多い順。
- 各リストは先頭 5 件を表示し、残りは「もっと見る」に入る。
- 割合は整数に丸めて表示し、件数を併記する。グループ別の円グラフは小数 1 桁。
- 意見のアイコンは 6 種類から毎回ランダムに選ばれる（画像の一致を検証するテストはできない）。
- 作成直後で投票が 0 のテーマは、すべて 0% で CSV の順に並ぶ。グループ別の表示は出ない。

### 4.4 pol.is 埋め込みについて

- アプリは `.polis` 要素に conversation_id を設定して `embed.js` を読み込むだけで、投票の通信には関与しない。
- 詳細画面を開いただけで pol.is 側に参加者データが作られるかどうかは、このリポジトリのコードからは判断できない。Polis の一般的な動作では、参加者は最初の投票または投稿の時点で作られる。
- 埋め込みの中のボタンを押せば、実データになる。

### 4.5 パラメータが無い・正しくないとき

- `conversation_id` が無い、または themes.csv に載っていないとき、分析は描画されず、エラーの表示も出ない。共有ボタンは反応しない。お気に入りボタンは `conversation_id` が空のとき非表示になる。
- テーマが公開された直後は、CSV の反映前にこの状態になることがある。

| | 入力クリア | `.clear-button[data-target]` |
| ボタン | 次へ | `.next-button[data-control-no]` |
| | **AI 生成（C2）** | `#axis-stepper .ai-generate-button`、`#comments-stepper .ai-generate-button`、`#description-stepper .ai-generate-button` |
| | **テーマを作成（C3）** | `#post-stepper .post-button` |
| 完了 | オーバーレイ | `.complete-overlay.show`、`.complete-close-button` |

### 5.2 ステップ

| 番号 | AI アシストモード | マニュアルモード |
| --- | --- | --- |
| 1 | テーマ（`#theme-stepper`） | テーマ |
| 2 | 立場 2 つ（`#axis-stepper`）＋AI 生成 | 意見 15 個（`#comments-stepper`） |
| 3 | 意見 8 個（`#comments-stepper`）＋AI 生成 | 説明（`#description-stepper`） |
| 4 | 説明（`#description-stepper`）＋AI 生成 | カテゴリ（`#category-stepper`） |
| 5 | カテゴリ（`#category-stepper`） | 投稿（`#post-stepper`） |
| 6 | 投稿（`#post-stepper`） | 完了 |
| 7 | 完了 | — |

### 5.3 入力の規則

- 各ステップの欄がすべて埋まると、そのステップの「次へ」が押せるようになる。
- AI 生成ボタンは、それより前のステップがすべて埋まっているときだけ押せる。
- 「テーマを作成」は、全ステップが埋まっているときだけ押せる。
- 文字数の上限はタイトル 80・説明 200。超えた状態で「次へ」を押すと、「タイトルは80文字以内で入力してください」／「説明は200文字以内で入力してください」と表示して進まない。サーバー側も同じ上限で検査する。
- 立場と意見の欄には上限が無い。
- マニュアルモードは、文言が「※ 8個の意見が必要です。」だが、実際は 15 欄すべての入力が必要である。

### 5.4 通信

| 操作 | 宛先 | 送る内容 | 実際に起きること |
| --- | --- | --- | --- |
| 立場の AI 生成 | `POST /theme/generate_axis` | アクセスキー、タイトル | OpenAI（gpt-5-nano）と Web 検索を呼ぶ。**費用が発生**。保存はしない |
| 意見の AI 生成 | `POST /theme/generate_comments` | アクセスキー、タイトル、立場 | 同上 |
| 説明の AI 生成 | `POST /theme/generate_descriptions` | アクセスキー、タイトル、立場、意見 | 同上 |
| テーマを作成 | `POST /theme/post_draft` | アクセスキー、タイトル、意見、説明、カテゴリ | 下書きが承認済みで登録され、**約 15 分以内に pol.is に実テーマが作られて一般公開される** |

- 通信に失敗しても、利用者向けのエラー表示は出ない。
- モーダルを開く、モードを切り替える、入力する、「次へ」を押す、までは通信が発生しない。

### 5.5 投稿後の流れ

1. 完了オーバーレイを表示し、そのモードの下書きと入力を消して、ステップ 1 に戻す。
2. サーバー側では、15 分ごとのバッチが古い順に 1 件ずつ pol.is へ投稿する。
3. 投稿されると themes.csv に追加され、ホームの一覧に出る。
4. 画面の文言は「テーマは審査通過後に全体に公開されます」だが、現状は人手の審査を挟まずに公開される。

### 5.6 安全に操作できる範囲

AI 生成ボタンを押さずに、すべての欄を手入力して「次へ」を進めれば、投稿ステップ（「テーマを作成」が押せる状態）まで B の範囲で到達できる。その先の「テーマを作成」を押すと C3 になる。

  - 入力（メールアドレス、お名前、お問い合わせ内容）→ 確認 → 完了の 3 画面。

### 7.2 管理画面（admin.pol-is.jp）

ファイル: `Client/public_html_admin/`

- **アクセス制限**: 許可された IPv4 アドレス以外は 403（CloudFront Function）。IPv6 は常に 403。API 側も `/admin/*` は許可 IP のみ。
- **アクセスキー**: `#identify-html-textarea` に入力して「セット」を押すと `/admin/info` を呼び、成功すれば Cookie `admin_access_key`（30 日）に保存する。次回以降は自動で一覧を読む。
- **一覧**: 論理削除されていない下書きの全件を、新しい順に表示する（投稿済みも含む）。各カードはタイトル、カテゴリ、作成日、説明、コメントを編集できる。
  - 「NEW!」タグは全件に常に表示される。
  - 「投稿失敗」タグは、投稿に失敗して隔離された下書き（FAILED）にだけ表示される。
  - 承認待ち・投稿済みを見分ける表示は無い。

| ボタン | 呼ぶ API | 実際に起きること |
| --- | --- | --- |
| セット | `POST /admin/info` | 一覧を読む（読み取りのみ） |
| 各下書きの「更新」 | `POST /admin/edit` | 下書きの内容を書き換える |
| 各下書きの「承認」 | `POST /admin/approve` | 承認済みにし、リトライ回数を 0 に戻す。15 分以内に pol.is へ投稿される。押せるのは、未承認か投稿失敗の下書きだけ |
| 各下書きの「削除」 | `POST /batch/delete` | 一覧（themes.csv）とレポート CSV から消し、下書きを論理削除する。**確認ダイアログは出ない**。pol.is 上の議題は消えない |
| 変換欄の「生成」 | `POST /batch/generate` | API 側に存在しないため動かない |
| 変換欄の「更新」 | `POST /batch/create_all` | 本番では必ず失敗する。失敗するたびに、最も古い承認済み下書きのリトライ回数が増える。**押さないこと** |

- 却下の機能は無い。不要な下書きは削除する。
- `localhost` から開いた場合も、本番の API を操作する。
